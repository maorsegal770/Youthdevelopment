## 1. רקע ובעיה

רחל לאה מעבירה קורסי הכנה ללידה ומעניקה ליווי לידה (דולה). כיום הפניות מגיעות מפה לאוזן ובוואטסאפ, אין מקום אחד שמציג את השירותים, ואין דרך למכור את תכני הקורס בצורה דיגיטלית.

**הבעיות:**
1. יולדות פוטנציאליות לא מוצאות מידע מסודר על השירותים.
2. פניות "הולכות לאיבוד" – אין תיעוד ואין מעקב.
3. אין הכנסה פסיבית מתכנים דיגיטליים.
4. כל שינוי בתוכן האתר דורש איש טכני.

## 2. מטרות

## 5. ארכיטקטורה טכנית

| שכבה | טכנולוגיה | עלות התחלתית |
|---|---|---|
| Frontend | React 18 + Vite + Tailwind, RTL | – |
| אחסון האתר | Netlify (או Vercel) | חינם |
| התחברות | Supabase Auth (מייל + סיסמה, OTP, איפוס סיסמה) | חינם עד 50K משתמשות |
| מסד נתונים | Supabase PostgreSQL + Row Level Security | חינם עד 500MB |
| פונקציות שרת | Supabase Edge Functions (Deno) | חינם עד 500K קריאות |
| מייל לידים | Resend | חינם עד 3,000 בחודש |
| סליקה | Stripe Checkout (או ספק ישראלי) | עמלת עסקה בלבד |

```
┌──────────── דפדפן (React, Netlify) ────────────┐
│ Landing · Register · Login · Lessons · Leads   │
└──────┬──────────────────────────────┬──────────┘
       │ supabase-js (Auth + REST)    │ functions.invoke
       ▼                              ▼
┌──────────────── Supabase ──────────────────────────────┐
│ PostgreSQL + RLS:                                       │
│  • profiles        – שורה לכל משתמשת (נוצרת בטריגר)    │
│                      role / subscription_status 🔒      │
│  • landing_sections – קריאה: כולם | כתיבה: admin       │
│  • course_lessons   – קריאה: admin / מנוי פעיל          │
│  • leads            – admin בלבד (נוצר דרך פונקציה)     │
│ Edge Functions:                                         │
│  • submit-lead      → שמירה + מייל דרך Resend           │
│  • create-checkout  → Stripe Checkout URL               │
│  • verify-checkout  → אימות תשלום + הפעלת מנוי          │
│  • stripe-webhook   → checkout.session.completed        │
└───────────────┬───────────────────────┬────────────────┘
                ▼                       ▼
        Stripe Hosted Checkout       Resend → Gmail
```

**זרימת תשלום:**
1. משתמשת מחוברת → `create-checkout` יוצר Session עם `client_reference_id = user.id`.
2. הפניה לדף Stripe; הכרטיס מוזן אצל Stripe בלבד.
3. Stripe → `stripe-webhook` (מאומת בחתימה) → `subscription_status = active`.
4. במקביל, דף ההצלחה קורא ל-`verify-checkout`, ששולף את ה-Session מ-Stripe ומוודא שהוא שייך למשתמשת ושולם. (כפילות מכוונת – הגישה נפתחת גם אם ה-Webhook מתעכב או אם הלשונית נסגרה.)

**הערה על ספק סליקה:** המימוש משתמש ב-Stripe. אם Stripe אינו זמין לעסק ישראלי בחשבון של רחל לאה, או אם רוצים Bit / תשלומים / חשבונית אוטומטית – מומלץ להחליף ל-**Grow (משולם)**, **Cardcom** או **Tranzila**. הזרימה זהה (דף סליקה מתארח + Webhook), וההחלפה מוגבלת לקובץ `supabase/functions/_shared/stripe.ts` ולשלוש פונקציות.

## 6. מודל נתונים

| טבלה | שדות עיקריים | הרשאות (RLS) |
|---|---|---|
| **profiles** | id (= auth.users), email, display_name, phone, due_date, role, subscription_status, stripe_customer_id, paid_at | קריאה: עצמה או admin. עדכון: עצמה, רק display_name / phone / due_date |
| **landing_sections** | kind (hero/about/service/topic/faq/text), title, body, icon, sort_order | קריאה: כולם. כתיבה: admin |
| **course_lessons** | module, title, summary, body, video_url, attachment_url, duration_minutes, sort_order, published | קריאה: admin, או מנוי פעיל לשיעורים מפורסמים. כתיבה: admin |
| **leads** | full_name, phone, email, interest, due_date, message, status, email_sent | admin בלבד. יצירה: רק פונקציית השרת |

ההרשאות נבדקו מול PostgreSQL 16: גולשת אנונימית לא רואה שיעורים ולא יכולה ליצור לידים ישירות; משתמשת שלא שילמה לא רואה שיעורים ולא יכולה לשנות לעצמה role או subscription_status; מנויה רואה רק שיעורים מפורסמים; admin עורכת הכל.
