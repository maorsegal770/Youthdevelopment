## 1. רקע ובעיה

רחל לאה מעבירה קורסי הכנה ללידה ומעניקה ליווי לידה (דולה). כיום הפניות מגיעות מפה לאוזן ובוואטסאפ, אין מקום אחד שמציג את השירותים, ואין דרך למכור את תכני הקורס בצורה דיגיטלית.

**הבעיות:**
1. יולדות פוטנציאליות לא מוצאות מידע מסודר על השירותים.
2. פניות "הולכות לאיבוד" – אין תיעוד ואין מעקב.
3. אין הכנסה פסיבית מתכנים דיגיטליים.
4. כל שינוי בתוכן האתר דורש איש טכני.

## 2. מטרות

### 4.3 דרישות לא-פונקציונליות

| תחום | דרישה |
|---|---|
| **אבטחה** | HTTPS בלבד; סיסמאות מנוהלות ע"י Base44 Auth (hash); הרשאות RLS ברמת המסד; אימות חתימת Webhook (HMAC-SHA256, חלון 5 דק'); מפתחות סודיים רק ב-Secrets של השרת |
| **תשלומים** | Hosted Checkout בלבד (PCI-DSS SAQ-A); אין שמירת מספרי כרטיס |
| **פרטיות** | עמידה בחוק הגנת הפרטיות ותקנות אבטחת מידע; מדיניות פרטיות ותנאי שימוש; איסוף מינימלי; מידע רפואי לא נאסף |
| **ביצועים** | LCP < 2.5 שניות במובייל 4G |
| **נגישות** | יעד WCAG 2.1 AA / ת"י 5568 (חובה בישראל לעסק המספק שירות לציבור): ניווט מקלדת, ניגודיות, תוויות לשדות, הצהרת נגישות |
| **זמינות** | 99.5% (תשתית Base44) |
| **SEO** | כותרות סמנטיות, meta description, Open Graph לשיתוף בוואטסאפ |
| **רספונסיביות** | 360px ומעלה, ללא גלילה אופקית |

## 5. ארכיטקטורה טכנית

```
┌────────────── דפדפן (React + Vite, RTL) ──────────────┐
│ Landing · Register · Login · Lessons · Leads          │
└───────┬───────────────────────────────┬───────────────┘
        │ Base44 SDK (Auth / Entities)  │ functions.invoke
        ▼                               ▼
┌──────────── Base44 Backend ─────────────────────────────┐
│ Entities (RLS):                                          │
│  • User (+display_name, phone, due_date,                 │
│          subscription_status 🔒, stripe_customer_id 🔒)  │
│  • LandingSection  – קריאה: כולם | כתיבה: admin         │
│  • CourseLesson    – קריאה: admin / מנוי פעיל            │
│  • Lead            – admin בלבד (נוצר דרך פונקציה)       │
│ Functions (Deno):                                        │
│  • submitLead            → שמירה + SendEmail לרחל לאה    │
│  • createCheckoutSession → Stripe Checkout URL           │
│  • verifyCheckout        → אימות תשלום + הפעלת מנוי      │
│  • stripeWebhook         → checkout.session.completed    │
└──────────────────────────────┬──────────────────────────┘
                               ▼
                    Stripe Hosted Checkout
```

**זרימת תשלום:**
1. משתמשת מאומתת → `createCheckoutSession` יוצר Session עם `client_reference_id = user.id`.
2. הפניה לדף Stripe; הכרטיס מוזן אצל Stripe בלבד.
3. Stripe → Webhook `stripeWebhook` (מאומת בחתימה) → `subscription_status = active`.
4. במקביל, דף ההצלחה קורא ל-`verifyCheckout`, ששולף את ה-Session מ-Stripe ומוודא שהוא שייך למשתמשת ושולם. (כפילות מכוונת – גישה נפתחת גם אם ה-Webhook מתעכב או אם הלשונית נסגרה.)

**הערה על ספק סליקה:** המימוש משתמש ב-Stripe. אם Stripe אינו זמין לעסק ישראלי בחשבון של רחל לאה, או אם רוצים Bit / תשלומים / חשבונית אוטומטית – מומלץ להחליף ל-**Grow (משולם)**, **Cardcom** או **Tranzila**. הזרימה זהה (דף סליקה מתארח + Webhook), וההחלפה מוגבלת לקובץ `base44/shared/stripe.ts` ולשתי פונקציות.
